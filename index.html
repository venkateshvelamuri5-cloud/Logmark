How it works

From a folder of files to an answer you can check.

Keep scrolling. The shape on screen follows your documents through each stage.

01 · ADD

Add your documents

Drop in PDFs, Word files, spreadsheets, CSVs or plain text. Logmark extracts the text page by page and sheet by sheet, and everything stays on your machine.

  • PDF pages, Word headings and tables, every Excel sheet
  • Identical files are skipped; changed files replace the old version
  • Only extracted text and vectors are kept, not copies of the files
02 · SPLIT

Split by meaning, not by character count

Semantic chunking cuts on whole sentences into passages of about 150 to 225 words, with a little overlap so nothing falls between the cracks.

  • Never mixes two chapters in one passage
  • Each passage carries its heading path and page range
  • Repeated page headers are removed
03 · FIND

Find the right passage

Hybrid search blends meaning-based embeddings with BM25 keyword matching, then a cross-encoder reranker rescores the best 30 candidates.

  • Near-duplicate passages are dropped and results kept varied
  • Each hit is merged with its neighbouring text for context
  • Passages are never cut off mid-sentence to fit the model
04 · ANSWER

Answer with citations, or say "not found"

The model answers only from the numbered passages and cites them. If nothing relevant clears the bar, the model isn't called at all.

What's in the app today

Everything you need to build an assistant you can trust.

Logmark is the product; SLM Forge is the engine room behind it. Here's what ships in the current build.

Small models, on your own machine

Run open GGUF models such as Qwen 2.5 and Llama 3.2 locally through llama.cpp. No API key, and your documents never leave the computer.

llama.cpp · GGUF · CPU

Assistants over your documents

Give an assistant a set of documents and instructions. It answers from them using retrieval, so the model's weights never change and there's no training run to wait for.

RAG · no fine-tuning

Cited answers and honest refusals

Every answer lists the files and pages it used. Answers without citations get a warning, and off-topic questions get a clear "not found".

sources line · [n] citations

Datasets and evaluation

Generate question-and-answer sets from your own documents, then score your assistants with AI-assisted (RLAIF) and human (RLHF) feedback before you rely on them.

Q&A generation · RLAIF · RLHF

Share an assistant

Share an assistant you've built with a link, or drop a small chat widget onto a web page, like the one in the corner of this site.

share link · embeddable widget

Optional cloud compute

When a job is too heavy for a laptop, you can choose to run it on Google Cloud compute. Day-to-day use stays on your own machine.

optional · GCP
Under the hood

A small, fast engine. No database to run.

Retrieval runs in logmark-core, a Rust engine that keeps every document collection as a folder of plain files.

STORAGE

A manifest, a passages file and a vectors file per collection. Easy to back up, move or delete.

SAFETY

The manifest is written last, so a half-finished write is ignored. A lock stops two indexing runs from colliding.

LOCAL ONLY

The engine's server listens on 127.0.0.1 and only accepts requests from the app itself.

FALLBACK

If the embedding model is missing, search falls back to keywords and says so instead of crashing.

logmark-core · example session
# index a folder of HR policies
> logmark-core index -c hr -p "C:\docs\policies"
  indexed 42 documents · 1,318 passages

# ask a question, get cited passages back
> logmark-core search -c hr -q "how many leave days" -k 5
  [1] leave-policy.docx · p.3   score 0.91
  [2] handbook-2026.pdf · p.17  score 0.84
  [3] leave-policy.docx · p.4   score 0.78

# what's on disk
  corpora/hr/manifest.json
  corpora/hr/chunks.3.jsonl
  corpora/hr/vectors.3.f32
